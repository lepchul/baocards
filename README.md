# Bao Cards

Готовый Telegram-бот на Python 3.12, aiogram 3 и SQLite. Админ-панель находится внутри Telegram, открывается командой `/admin` в личном чате. Отдельный сайт не нужен.

## Быстрый запуск на хостинге с Docker

1. Создай бота через официальный Telegram-аккаунт **@BotFather**, команда `/newbot`. Получи токен.
2. Распакуй архив и открой папку `bao-cards`.
3. Скопируй `.env.example` в `.env`. Вставь токен после `BOT_TOKEN=`. Не отправляй `.env` в публичный репозиторий.
4. Открой `config.json`. Замени `123456789` на свой числовой Telegram ID. Для нескольких админов: `{"admin_ids": [111111111, 222222222]}`. Если ID неизвестен, можно сначала запустить бота с примером конфига, написать `/id`, затем заменить ID и перезапустить.
5. Запусти из папки проекта:

```bash
docker compose up -d --build
```

6. Напиши боту `/start`, затем `/admin`. Нажми **Добавить карту**. Последовательно отправь название, ID редкости, стоимость, очки и картинку как фото. Для первой карты можно указать: `Бао`, `1`, `50`, `20`, затем свое фото.
7. Напиши `бао`. Бот выдаст карту с изображением и уникальным ID.

Каталог намеренно пустой: карты и картинки добавляются владельцем. До добавления первой карты бот не списывает время ожидания. Начальные редкости уже созданы: Обычная (вес 70), Редкая (23), Легендарная (7).

Управление контейнером:

```bash
docker compose logs -f --tail=100
docker compose restart
docker compose down
```

После изменения `config.json` нужен перезапуск. Настройки, измененные через панель, применяются сразу. Не выполняй `docker compose down -v`: флаг `-v` удаляет том с игроками и картами.

## Запуск на обычном Python-хостинге

Нужны Python 3.12, исходящие HTTPS-соединения к Telegram и постоянный диск. Тип процесса - worker, команда запуска `python bot.py`. HTTP-порт не требуется. Запускай только **один экземпляр** на один токен и одну базу.

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполни .env и config.json
python bot.py
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Заполни .env и config.json
python bot.py
```

На панели хостинга можно передать `BOT_TOKEN`, `DATABASE_PATH` и `CONFIG_PATH` через переменные окружения вместо `.env`. Приоритет у переменных окружения. `DATABASE_PATH` должен указывать на постоянный диск, например `/data/bao.sqlite3`. Хостинг с засыпающим процессом или временным диском для постоянной игры не подходит.

Для VPS без Docker можно настроить systemd по примеру `deploy/bao.service`. В нем нужно заменить пользователя и путь. Не запускай одновременно systemd и Docker с одним токеном.

## Работа в группах

- В `/start` есть кнопка добавления в группу.
- В @BotFather выбери `/setprivacy`, своего бота, затем `Disable`, чтобы бот получал обычные фразы вроде `бао`.
- После смены настройки удали и снова добавь бота в группу, если Telegram не применил режим к уже добавленному боту.
- Разреши боту отправлять сообщения и фото. Выдавать права удаления сообщений, банов и прочие права админа не требуется.
- Команда `/bao@имя_бота` позволяет явно обратиться к боту.
- Анонимные сообщения от имени группы или канала не участвуют в игре.
- Админ-панель и выгрузки доступны только в личке и только ID из конфига.

Официальное описание режима приватности: https://core.telegram.org/bots/faq#what-messages-will-my-bot-get

## Команды игрока

| Команда | Действие |
| --- | --- |
| `/start` | Меню и добавление в группу |
| `бао` или `/bao` | Открытие карты |
| `/cards` | Коллекция с перелистыванием |
| `/card 123456789012` | Показать свою карту с фото |
| `/profile` | Аватарка, монеты, очки, статистика, таймер |
| `/buyer` | Скупщик: выбор карты и подтверждение продажи |
| `/send @username 123456789012` | Передача с подтверждением и указанием ID получателя |
| `/send 123456789012` ответом на сообщение | Передача автору сообщения, в том числе без username |
| `/fav 123456789012` | Включить или снять защиту от продажи и передачи |
| `/upgrade` | Купить постоянное сокращение интервала |
| `/top` | Всемирный топ-20 |
| `/history` | Последние операции игрока |
| `/id` | Числовой Telegram ID |
| `/help` | Помощь |
| `/cancel` | Отмена текущего ввода администратора |

Игрок без доступной боту аватарки получает текстовый профиль. Бот не может написать в личку игроку, который не начинал с ним диалог. Поэтому отсутствие личного уведомления не отменяет успешную передачу: карта уже находится в коллекции получателя.

Telegram Bot API не позволяет произвольно найти незнакомого человека по username. Для `/send @username ID` получатель должен быть известен боту. Username обновляется при новых сообщениях пользователя и может устареть, если человек поменял его вне бота. В подтверждении показываются имя и постоянный Telegram ID. Надежнее передавать ответом на свежее сообщение игрока.

## Игровые правила

- У каждого экземпляра карты собственный случайный 12-значный ID. Он остается прежним при передачах.
- Время открытия общее для всех групп и лички: исходно 120 минут.
- Ускорение постоянное, 6 уровней по 15 минут, минимум 30 минут. Цена каждого шага по умолчанию 100 очков; администратор меняет ее в панели.
- Покупка ускорения сразу сокращает текущий таймер. Отсчет идет от последнего открытия.
- За выпадение выдаются очки. Продажа дает монеты. Передача не начисляет очки никому.
- Рейтинг учитывает все очки, заработанные при открытии. Покупки ускорений рейтинг не уменьшают. Заблокированные игроки в топе не видны.
- Примерное соотношение редкостей 70:23:7 работает, когда в каждой редкости есть активные карты. Пустые редкости не участвуют. Внутри выбранной редкости карты равновероятны.
- Дубликаты возможны: у них одинаковый вид, но разные ID экземпляров.
- Стоимость, очки, редкость, название и фото сохраняются в экземпляре при выпадении. Изменение каталога влияет на будущие выпадения. Скупщик всегда платит именно сохраненную сумму.
- Монеты пока являются балансом от продажи и отображаются в профиле. Покупки карт за монеты и вывод реальных денег не реализованы.
- Продажа и передача требуют подтверждения владельца; подтверждение действует 5 минут. Избранные карты защищены.

## Админ-панель

1. **Карты**: каталог с страницами, просмотр картинки, смена названия, редкости, цены, очков, фото, включение и выключение выпадения.
2. **Добавить карту**: пошаговый ввод. Фото загружается непосредственно в Telegram, бот хранит `file_id`.
3. **Редкости и шансы**: создание и редактирование названия и веса. Максимум 30 редкостей.
4. **Тексты и кнопки**: изменение игровых сообщений и подписей кнопок. `drop` - подпись выпавшей карты, `profile` - профиль, `welcome` - приветствие, `help` - помощь, `cooldown` - ожидание, `send_confirm` - подтверждение передачи. Другие ключи описаны в `texts.py`.
5. **5 фраз открытия**: ровно пять разных фраз, по одной на строке, до 60 символов. Регистр игнорируется, совпадение должно быть полным. `/bao` остается постоянной командой независимо от фраз.
6. **Цена ускорения**: очки за один шаг. Граница в 30 минут не меняется.
7. **Найти игрока**: поиск по ID или username, блокировка, снятие блокировки, корректировка монет и доступных очков с обязательной причиной, история операций CSV.
8. **Экспорт игроков**: все известные боту пользователи и их игровая статистика.
9. **Все операции CSV**: выдачи, продажи, передачи, ускорения, регистрации, изменения имен и административные изменения. Время `at` - Unix timestamp, UTC. `actor` и `target` - постоянные ID пользователей; `item` - ID экземпляра; `detail` - JSON подробностей.
10. **Резервная копия**: согласованная SQLite-копия прямо в личный чат администратора.

В шаблонах нужно сохранять исходные переменные в фигурных скобках. Например, в `drop` используются `{name}`, `{rarity}`, `{price}`, `{points}`, `{id}`. HTML и Markdown не интерпретируются. `/reset` при редактировании текста возвращает стандартный шаблон. Длинные тире автоматически заменяются на `-`. Если развернутый пользовательский шаблон превышает лимит Telegram, бот использует исходный текст для этого сообщения.

Сессии ввода администратора истекают через 30 минут и сбрасываются после перезапуска. Кнопка главного меню `/admin` также отменяет текущий ввод. Изменения, уже сохраненные в базе, остаются.

## Данные и защита от повторных операций

- Продажи, передачи, очки, таймеры и аудит изменяются в одной SQLite-транзакции `BEGIN IMMEDIATE`.
- Два одновременных открытия не создадут две карты. Одновременные продажа и передача одной карты имеют только одного победителя.
- Каждый запрос открытия по сообщению имеет уникальный ключ. Повторно доставленное сообщение не выдает новую карту.
- Подтверждения привязаны к числовому ID игрока. Чужую кнопку нельзя использовать.
- При продаже или передаче другие старые подтверждения для этой карты удаляются.
- Кнопки повторно проверяют владельца карты, защиту, блокировки и баланс в момент выполнения.
- Изменение каталога не подменяет цену ранее полученной карты.
- SQL-запросы используют параметры. CSV защищен от формул в именах пользователей.
- Обычная переписка не сохраняется. Учет ID, имени, username и игровых действий описан в `/help`.
- Логи позволяют расследовать передачи, но не определяют автоматически, принадлежат ли разные Telegram-аккаунты одному человеку.
- Архив не содержит токена или настоящих данных пользователей.

Операционная модель: один polling worker, локальная SQLite на постоянном диске. Для большой нагрузки или нескольких реплик потребуется отдельная миграция на серверную БД и очередь. CSV-экспорт выполняется по запросу и может занимать время при большом журнале.

## Резервное копирование и восстановление

Через `/admin` нажми **Резервная копия** и сохрани файл отдельно от сервера. Можно также запустить:

```bash
python backup.py
```

В Docker:

```bash
docker compose exec bao python backup.py --output /app/data/backups
docker compose cp bao:/app/data/backups ./backups
```

Для автоматических копий запускай эту команду по расписанию хостинга. Переноси копии на другой диск. Автоматическая отправка админам не включена.

Восстановление без Docker: останови бота, сохрани текущую базу и сопутствующие файлы `-wal` и `-shm` отдельно, убери старые файлы из рабочего каталога, скопируй резервную копию на путь `DATABASE_PATH`, затем запусти бота. Не заменяй базу во время работы.

Восстановление Docker (файл резервной копии в текущей папке):

```bash
docker compose stop bao
docker compose run --rm --user root -v "$PWD:/restore:ro" bao python -c "from pathlib import Path; import shutil,os; p=Path('/app/data/bao.sqlite3'); [x.unlink(missing_ok=True) for x in (p,Path(str(p)+'-wal'),Path(str(p)+'-shm'))]; shutil.copyfile('/restore/bao-backup.sqlite3',p); os.chown(p,10001,10001)"
docker compose up -d
```

Перед восстановлением обязательно сохрани текущие данные, если они нужны. Фото `file_id` привязаны к токену бота: при переходе на другого бота изображения нужно загрузить заново. Смена сервера при сохранении того же бота не требует повторной загрузки фото.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты работают без токена и реальных Telegram-запросов. Они проверяют экономику, конкурентные операции, права кнопок, маршрутизацию команд, админ-сценарии, таймеры, перезапуск и резервную копию. Перед приемом игроков проверь на своем боте: добавление фото, открытие, продажу, передачу второму аккаунту, аватарку, группу и восстановление резервной копии.

Документация зависимостей: https://docs.aiogram.dev/en/v3.28.2/
